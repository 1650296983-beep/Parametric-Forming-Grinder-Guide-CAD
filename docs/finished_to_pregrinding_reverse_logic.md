# 成品规格倒推成型磨前规格：现有规则梳理

## 1. 结论与适用边界

当前“成型磨导轨 CAD 参数化生成器”**没有实现**“只输入成品规格，自动计算出成型磨前规格”的公式或模型。它采用的是“双规格输入”模型：

- 成品规格描述最终轮廓和最终尺寸；
- 成型磨前规格描述进入成型磨工序时的真实包络、尺寸公差和厚度公差；
- 程序根据两者、磨前形态和机台规则，决定导轨型腔，而不是由成品规格反算磨前尺寸。

因此，下面内容应作为新项目的**规则依据、数据契约和反推边界**，不能直接理解为已经得到一套通用的“成品 → 磨前”尺寸计算公式。现有数据能够可靠支持的反向结论是：

1. 可由“成品形态 + 已确认工艺路线”确定候选磨前形态；
2. 可由某些成品尺寸约束磨前规格的合法性；
3. 不能由现有规则唯一确定磨前宽度、厚度、上下公差或同 R 半径；这些必须来自工艺卡、历史批次、设备能力或人工审批的余量规则。

新项目若要继续倒推“磨前 → 毛坯”，应保持同一原则：每一级规格必须单独建模，并记录其来源和置信度；绝不能把下游尺寸或导轨参数伪装成已确认的上游规格。

## 2. 术语与规格格式

所有尺寸单位均为 mm。为避免“宽度”在不同截面中含义混淆，本文统一使用“弦宽/通过宽度”表示截面左右端点之间的直线距离，不是弧长。

| 层级 | 形态 | 当前项目规格格式 | 关键字段 |
|---|---|---|---|
| 成品 | 瓦型 `tile` | `R外*R内*弦宽*长度*成品厚度` | 两个最终 R、成品弦宽、长度、成品厚度 |
| 成品 | 馒头/面包型 `bread` | `R*长度*宽度*成品厚度` | 单个最终 R、长度、宽度、成品厚度 |
| 成型磨前 | 方块 `block` | `长度*宽度(上偏差/下偏差)*厚度(上偏差/下偏差)` | 通过宽度及公差、厚度及公差、长度 |
| 成型磨前 | 同 R 瓦型 `same_r_tile` | `R*R*弦宽(上偏差/下偏差)*长度*厚度(上偏差/下偏差)` | 相等的上下 R、弦宽及公差、厚度及公差、长度 |

示例：

```text
# 成品瓦型
R16.3*R14.3*5.00*20*2.00

# 成型磨前方块
20*5.00(-0.01/-0.03)*2.25(+0.01/-0.01)

# 成型磨前同 R 瓦型
R30*R30*17.4(+0/-0.02)*23.5*3.95(+0.02/-0.02)
```

成品瓦型的第五项是独立的成品壁厚，不能从 `R外 - R内` 自动补算或替代。成品馒头型只有一个 R；禁止用“R 减厚度”伪造第二个 R。

## 3. 必须保留的双规格数据模型

现有项目的核心经验是：成品和磨前不是同一规格的两个写法，而是两个独立工序状态。新项目至少应保存下列结构化字段。

```json
{
  "finished": {
    "shape": "tile | bread",
    "spec": "原始规格字符串",
    "dimensions": {},
    "source": "图纸/OCR/人工录入"
  },
  "pre_grinding": {
    "shape": "block | same_r_tile | 未确认",
    "spec": "原始规格字符串或待计算结构化字段",
    "dimensions": {},
    "tolerances": {},
    "derivation_status": "confirmed | rule_derived | needs_review",
    "rule_id": "工艺路线或余量规则版本",
    "evidence": []
  }
}
```

`shape` 必须显式输入或由已批准的工艺路线给出，不能通过规格中有几个 `R`、成品是否为瓦型等字符串特征猜测。现有程序中，相同的瓦型成品可对应方块磨前或同 R 瓦型磨前，两条路径的导轨型腔完全不同。

## 4. 已实现的工艺分流（可作为反推候选路径）

下表是当前项目实际支持的成品/磨前组合。它是新项目建立“候选磨前形态”规则表的最可靠起点。

| 成品形态 | 磨前形态 | 工艺类型 | 可从成品得到的结论 | 不能从成品得到的字段 |
|---|---|---|---|---|
| 瓦型 `tile` | 方块 `block` | `block_to_tile` | 需一平一弧型腔；主 R 取 `max(成品外R, 成品内R)` | 方块宽、厚、各公差、实际加工余量 |
| 馒头型 `bread` | 方块 `block` | `block_to_bread_rectangular` | 磨前包络为矩形；成品单 R 仅是磨后目标 | 方块宽、厚、各公差、实际加工余量 |
| 瓦型 `tile` | 同 R 瓦型 `same_r_tile` | `same_r_tile` | 磨前应提供上下相等 R 的独立规格 | 同 R 的具体半径、弦宽、厚度、各公差 |
| 馒头型 `bread` | 同 R 瓦型 | 当前未支持 | 必须人工确认工艺路线 | 全部磨前规格 |

这张表并不表示“瓦型一定倒推为方块”或“瓦型一定倒推为同 R”。同一成品规格至少存在前两类候选，因此仅凭成品规格的反推是多解问题。

### 4.1 瓦型成品 → 方块磨前候选

当工艺路线明确为方块磨瓦时，现有系统使用以下关系：

```text
finished_shape = tile
pre_grinding_shape = block
process_type = block_to_tile
R_form = max(finished_R_outer, finished_R_inner)
```

`R_form` 是导轨型腔使用的工艺 R，不是方块磨前产品已经具有的 R。方块磨前产品的截面仍为矩形。主 R 面在第一砂轮侧，平面和通常的圆心在其对侧；这是导轨定向规则，不是规格尺寸的反推规则。

特殊情况：当 `finished_R_inner - finished_R_outer > 10.00` 时，当前实现只翻转主弧的圆心侧，主 R 仍取两个成品 R 的较大值，方块磨前尺寸也不会因此发生变化。

可执行的合法性约束：

```text
abs(pre_grinding.length - finished.length) <= 0.01
```

因此，长度通常可按等长作为候选初值或校验条件，但现有代码没有任何“长度余量”反推规则。

### 4.2 馒头型成品 → 方块磨前候选

当工艺路线明确为方块磨馒头型时：

```text
finished_shape = bread
pre_grinding_shape = block
process_type = block_to_bread_rectangular
```

成品单 R 不进入磨前方块的几何定义，也不能用于计算方块厚度或宽度。当前项目仅要求磨前方块与成品等长（误差不大于 `0.01` mm）。

成品馒头规格写法可能存在“长度、宽度”顺序差异。现有解析器只有在已经取得磨前方块长宽后，才可用以下匹配消歧：

```text
abs(finished.length - pre_grinding.length) <= 0.01
abs(finished.width  - pre_grinding.width)  <= 0.25
```

这是一项**已知磨前规格后的格式消歧**，不是由成品反算方块长宽的逻辑。

### 4.3 瓦型成品 → 同 R 瓦型磨前候选

当工艺路线明确要求同 R 磨前产品时，磨前规格必须独立提供，且满足：

```text
pre_grinding.R_outer == pre_grinding.R_inner
```

现有系统不允许用成品异 R 自动改写为同 R，也不规定该同 R 应取成品外 R、内 R、较大 R 或其他值。导轨对该路线使用磨前的同 R，而不是成品 R。

## 5. 成品不能直接反推的尺寸及原因

以下字段在当前项目中均无合法的单向反推公式。新项目应将它们作为待配置的工艺规则输出，而不是默认为确定值。

| 磨前字段 | 为什么不能从成品唯一确定 |
|---|---|
| 磨前宽度 | 可能与成品宽度相同、偏大或偏小；历史实例中成品宽 `12.00`、磨前宽 `12.20`，证明二者不可替代。 |
| 磨前厚度 | 成型磨前余量随前道工序、磨削面、材料和质量要求变化；导轨的 `+0.12` 是导轨厚度间隙，不是产品磨前余量。 |
| 宽度/厚度上下公差 | 它们来自前道能力或工艺要求，不能由成品公差、R 值或导轨槽宽倒推。 |
| 方块或同 R 的磨前形态 | 相同瓦型成品可以走不同工艺路线。 |
| 同 R 瓦型的 R | 现有规则未定义其与最终两个 R 的映射。 |
| 长度余量 | 当前只做等长校验，没有定义长度方向预留。 |

尤其要避免下列错误推导：

```text
错误：pre_grinding_thickness = finished_thickness + 0.12
原因：0.12 是方块磨前产品生成导轨时的“导轨厚度间隙”，不是磨前产品余量。

错误：pre_grinding_width = finished_width
原因：成品宽度不能覆盖磨前宽度；两者可能不同。

错误：same_r = max(finished_R_outer, finished_R_inner)
原因：max(R) 仅适用于方块磨瓦时的导轨主弧，不是同 R 磨前产品半径。
```

## 6. 磨前规格已确认后可复用的计算规则

以下公式的方向是“磨前规格 → 导轨参数”，不是“成品 → 磨前规格”。它们可以用来校验新项目倒推出的候选规格是否与现有 CAD 规则兼容。

### 6.1 磨前尺寸中值

```text
preform_width_max = width_nominal + width_upper_tolerance
preform_width_min = width_nominal + width_lower_tolerance
preform_width_mid = (preform_width_max + preform_width_min) / 2

preform_thickness_mid = thickness_nominal
                      + (thickness_upper_tolerance + thickness_lower_tolerance) / 2
```

### 6.2 槽宽（用于导轨，不等于磨前宽度）

```text
width_tolerance_range = preform_width_max - preform_width_min
slot_clearance_mid = 0.04,  当 tolerance_range <= 0.02
slot_clearance_mid = 0.05,  当 tolerance_range >  0.02

slot_width_raw = preform_width_mid + slot_clearance_mid
slot_width = ROUND_HALF_UP(slot_width_raw, 0.01)
```

特殊工艺选项可显式把 `slot_clearance_mid` 改为：高对称度 `0.03`、大瓦放宽 `0.08`。这些是导轨通过间隙，也不得倒用为磨前产品余量。

### 6.3 导轨厚度（不是磨前厚度）

```text
guide_thickness = preform_thickness_mid + thickness_clearance_mid
```

默认 `thickness_clearance_mid`：方块 `0.12`；小瓦 `0.18`；弦宽大于 `15` 的大瓦 `0.25`；显式勾选“磨单边/高要求”时统一为 `0.09`。这些值用于导轨设计，不得写回为磨前产品的工序余量。

### 6.4 砂轮吃入量（不是磨前尺寸）

```text
requested_cut_in_depth = preform_thickness_mid * 0.6
notch_opening_limit = product_length * 0.6
```

自然开口超限时通过移动砂轮圆心限制开口；不会修改磨前厚度，也不能反推厚度。

## 7. 现有输入、校验与失败条件

新项目应继承这些防错约束：

1. 必须同时保存 `finished_spec`、`pre_grinding_spec`、成品形态和磨前形态。
2. 磨前方块进入导轨计算时，宽度和厚度都必须有上下公差；没有公差时不能计算正式槽宽/导轨厚度。
3. 若单独提供 `tolerance` 元数据，其值必须和磨前规格解析结果完全一致；不得用元数据覆盖规格原文。
4. 同 R 磨前规格的两个 R 必须严格相等。
5. 方块路线下，成品与磨前长度必须在 `0.01` mm 内一致；不一致必须人工确认，不可自动“补偿”。
6. 成品类型、磨前形态、砂轮顺序和机台坐标系必须显式记录；方向冲突时应停止生成，而不是自动镜像猜测。
7. 任何未支持的形态组合或缺少形态元数据的输入，都应返回 `needs_review`，不产生正式规格。

## 8. 面向“成品 → 磨前 → 毛坯”新项目的建议设计

建议将新项目实现为两段独立、可审计的逆向工艺链，而不是一个跨多道工序的加减余量公式：

```text
成品规格
  + 工艺路线/产品族/材料/设备能力
  → 候选成型磨前规格（含来源、规则版本、置信度）
  + 前道工艺路线/毛坯标准/收缩与切削余量规则
  → 候选毛坯规格（含来源、规则版本、置信度）
```

### 8.1 第一段：成品 → 成型磨前

输入除了成品规格外，至少还应要求：

- 产品族和材料牌号；
- 成型磨工艺路线标识（例如 `block_to_tile`、`block_to_bread_rectangular`、`same_r_tile`）；
- 需要磨削的面/砂轮顺序；
- 各方向成型磨余量规则和公差来源；
- 长度是否等长、是否允许端面余量；
- 规则版本、生效日期和批准人。

输出不要只给一个字符串；应给候选列表。例如：

```json
{
  "status": "needs_review",
  "finished_spec": "R24.7*12*46*2.1",
  "candidates": [
    {
      "pre_grinding_shape": "block",
      "length": {"value": 46.0, "source": "equal_length_rule"},
      "width": {"value": null, "source": "missing_allowance_rule"},
      "thickness": {"value": null, "source": "missing_allowance_rule"},
      "confidence": "low",
      "required_confirmation": ["width_allowance", "thickness_allowance", "tolerances"]
    }
  ]
}
```

只有所有加工余量、公差和形态规则都有受控来源时，候选才能升级为 `confirmed`。

### 8.2 第二段：成型磨前 → 毛坯

这一步不能复用导轨的槽宽间隙、导轨厚度间隙或砂轮吃入量。它需要单独的前道规则库，至少包括：

- 毛坯形态（块料、压型坯、烧结坯、线切割前坯等）；
- 各方向加工余量及其适用条件；
- 烧结/热处理收缩率与批次、材料和方向的关系；
- 倒角、圆角、装夹边、切断损耗等附加几何；
- 毛坯尺寸公差、检测基准与取整规则；
- 物料牌号、密度或质量约束（如适用）。

建议每条规则使用版本化的表驱动配置，并对每个输出字段记录 `source_rule_id`、计算公式、输入值和人工确认记录。

## 9. 可直接复用的验收用例

这些现有实例可作为新项目“不得混淆成品和磨前”的回归样本：

| 成品规格 | 已确认磨前规格 | 应得结论 |
|---|---|---|
| `R16.3*R14.3*5*20*2` | `20*5(-0.01/-0.03)*2.25(+0.01/-0.01)` | 方块磨瓦；候选长度 `20`；导轨主 R 为 `16.3`，但方块本身不带 R。 |
| `R9.6*8.6*42.6*2.1` | `42.6*8.6(-0.07/-0.09)*2.1(+0.01/-0.01)` | 方块磨馒头型；成品 R 不参与方块截面。 |
| `R24.7*12*46*2.1` | `46*12.2(-0.09/-0.11)*2.1(+0.01/-0.01)` | 成品宽 `12.0` 与磨前宽 `12.2` 不同；系统不得把成品宽覆盖磨前宽。 |
